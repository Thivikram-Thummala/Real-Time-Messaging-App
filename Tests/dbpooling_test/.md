# Database Connection Pooling Benchmark Report

## 1. Scenario

* **Target Database**: Local PostgreSQL
* **Dataset**:
  * **Users**: 5 test users (`pool_user_1` to `pool_user_5`)
  * **Rooms**: 2 test rooms (`Pool Test Room 1`, `Pool Test Room 2`)
  * **Messages**: 300 generated test messages in `Pool Test Room 1`
* **Test Parameters**:
  * **Concurrent Connection Requests**: 50 simultaneous queries(50 users opening a chat room and scrolling up to load the previous batch of message history)
  * **Max Pool Connections Allowed (`DB_POOL_MAX`)**: 20 connections (configured via `pg.Pool({ min: 2, max: 20 })`)

---

## 2. Metrics

| Metric | Without Pooling (New Client) | With Pooling (pg.Pool) | Improvement |
| :--- | :--- | :--- | :--- |
| **Total Batch Time** | 642 ms | 280 ms | **~2.3x faster** |
| **Avg Latency** | 397.17 ms | 136.15 ms | **~2.9x faster** (65.7% lower) |
| **p95 Latency** | 607.28 ms | 258.12 ms | **~2.4x faster** (57.5% lower) |
| **Min Latency** | 160.22 ms | 85.93 ms | **~1.9x faster** (46.4% lower) |
| **Max Latency** | 623.72 ms | 275.15 ms | **~2.3x faster** (55.9% lower) |

> **Summary**: Connection Pooling achieved a **~2.9x latency reduction** and a **~57.5% reduction in p95 tail latency** under 50 concurrent requests.
