# Media Streaming & CDN Delivery Benchmark Report

## 1. Scenario

  * Evaluated media transfer performance across 3 different file sizes using **Constant 64KB Buffer Streaming** (`streamifier`):
    1. **5 MB**: Small media (High-Res Chat Photos, Audio Notes).
    2. **20 MB**: Medium media (Short Video Clips, Document Batches).
    3. **50 MB**: Large media (HD Videos, Large File Attachments).
  * Compared **Before CDN** (Served through Node.js Origin App Server) vs. **After CDN** (Served via Cloudinary Edge Network).

  * Measured Node.js **Payload RAM Allocated** (`heapUsed`) during constant 64KB chunk streaming uploads.
  * Measured **Network Latency Metrics** (Avg, p95, p99, Min, Max) across multiple concurrent request iterations.

## 3. Key Takeaways & Performance Impact

### Key Takeaways
1. **Constant Buffer Memory Footprint**: Node.js memory consumption remains flat at **0.12 MB – 0.24 MB** regardless of whether a 5MB or 50MB file is transferred due to `streamifier` 64KB chunk streaming. Without streaming, a 50MB upload would consume **+50 MB of server RAM per concurrent user**.
2. **100% Server RAM & CPU Offloading with CDN**: Serving cached media from Cloudinary CDN Edge consumes **0.00 MB of Node.js RAM** and 0% app server CPU across all 3 scenarios.
3. **Improved Tail Latency for Large Files**: For large files, CDN delivery reduced p99 tail latency from **568.11 ms down to 335.06 ms** (~41.0% reduction).

### How It Improves Application Performance
* **Prevents Out-Of-Memory (OOM) Server Crashes**: Node.js heap memory usage stays constant under heavy concurrent media uploads.
* **Unblocks Real-Time Chat Messaging**: Offloading static media downloads to CDN keeps the Node.js single-threaded event loop completely free to handle low-latency WebSocket chat messages.
